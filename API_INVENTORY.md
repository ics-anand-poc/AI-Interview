# API Inventory — Frontend ↔ Backend

Generated by diffing every `route.ts` under the old project's `src/app/api/`
against the FastAPI routers in `Backend/routers/`. 113 endpoints across 92
route files; **12 are ported** to the Python Backend (8 interview/admin-auth
+ 4 employee-auth as of this pass), the rest still run as Next.js API
routes in `Frontend/src/app/api/` (kept as working code — not stubs — until
each is ported and the frontend call site is repointed at
`NEXT_PUBLIC_BACKEND_URL`).

This is a first pass: method + path + status only. Per-endpoint purpose,
request/response schema, auth requirement, and frontend caller (the rest of
item 53) still need to be filled in — that's naturally a by-product of
actually porting each one, so it'll grow alongside `Backend/README.md`'s
"Migrated so far" section rather than being written speculatively up front.

Static note: none of this has been exercised against a live Supabase
instance (this environment has no network path to Supabase/Azure/Groq) —
"ported" here means compiles clean and matches the original route's logic
on read, not live-verified. See `Backend/README.md` for the per-route
caveats on the 8 already ported.
